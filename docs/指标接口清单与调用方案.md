## AI 阅读指引

1. 调用任何接口前先执行「第 2 节：获取令牌」，拿到 `access_token` 并在后续请求头带 `Authorization: Bearer <token>`。
2. 指标标识**只能取自第 5 节清单**（系统指标编码或 Excel 科目编码），不得自行编造；清单里没有的标识会返回 `errors`（指标不存在）。
3. 只想拿一个总数 → 「第 4.4 节：只取合计」；要按组织拆分 → 第 4.3 节。
4. 判断成功看响应体 `code == 0`（不是 HTTP 200 以外的值），失败原因见第 6 节错误码。
5. 数值保留 4 位小数；单位见第 5 节（元 / 次 / % / 天）；只返回存在的行，缺失期间按 0 处理。
6. 第 5 节标注「组织维度=无」的指标不要传 `org_codes`，否则会被过滤成空结果。
7. 返回的每行都同时带 `metric_code`（系统编码）与 `excel_code`（财务 Excel 科目编码），可直接与财务底稿对账。

## 4. 取数接口 `POST /open/v1/metrics/query`

### 4.1 请求字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `metrics` | string[] | 是 | - | 指标标识数组，单次上限 20 个；可传系统指标编码（`marketing_office_expense`）或 Excel 科目编码（`EXP-01-a`），均见第 5 节 |
| `period_type` | string | 否 | `month` | `month` / `day` / `week` / `year`，须与指标的期间类型一致 |
| `period_start` | string | 否 | 当前期间 | 起始期间（含）；月 `2026-09`、日 `2026-09-28`、年 `2026` |
| `period_end` | string | 否 | 同 `period_start` | 结束期间（含）；单次跨度上限：月 36、日 366、年 10 |
| `org_codes` | string[] | 否 | 授权范围内全部组织 | 组织编码，例如 `["100","101"]`；编码见 `/open/v1/orgs` |
| `level` | string | 否 | `org` | `org` 组织合计行；`dept` 核算维度明细行；`all` 全部（后两者需应用开通明细权限） |
| `format` | string | 否 | `long` | `long` 长表（一行一个指标×期间×组织）；`wide` 宽表（指标做列） |
| `total_only` | bool | 否 | `false` | `true` 只返回合计：结果在 `totals`，`items` 为空 |
| `include_meta` | bool | 否 | `true` | 是否返回指标名称、单位、口径说明 |

### 4.2 响应字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 表示成功，其它值见第 6 节 |
| `data.items` | object[] | 明细行（长表）；`total_only=true` 时为空数组 |
| `data.totals` | object[] | 合计行（仅 `total_only=true`）：`metric_code`/`period_value`/`value`/`org_count`/`calc_time` |
| `data.rows` | object[] | 宽表行（仅 `format=wide`） |
| `data.metrics` | object[] | 本次请求指标的元信息（`code`/`name`/`excel_code`/`period_type`/`unit`/`dimensions`/`description`） |
| `data.errors` | object[] | 不可读的指标及原因（如「指标不存在」「指标已停用」） |
| `data.summary` | object | 汇总：`metric_count`/`item_count`/`period_count`/`org_count`/`total` |

指标元信息字段（`data.metrics[]`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 系统指标编码，用于 `metrics` 入参 |
| `name` | string | 指标名称 |
| `excel_code` | string | **Excel 科目编码**（财务底稿编码，如 `EXP-01-a`）；无对应编码时为 `null` |
| `period_type` | string | 期间类型 `month`/`day`/`week`/`year` |
| `unit` | string | 单位：元 / 次 / % / 天 |
| `dimensions` | string[] | 维度配置键（如 `org`、`dept`） |
| `description` | string | 口径说明 |

明细行字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `metric_code` | string | 指标编码 |
| `metric_name` | string | 指标名称（`include_meta=true` 时返回） |
| `excel_code` | string | **Excel 科目编码**（如 `EXP-01-a`），与财务底稿对账用 |
| `period_value` | string | 期间值，如 `2026-09` |
| `org_code` / `org_name` | string | 组织编码与名称；未映射组织的行可能为 `null` |
| `dept_code` / `dept_name` | string | 核算维度（部门/客户）；`level=org` 时恒为 `null` |
| `value` | number | 指标值（单位见 `data.metrics[].unit`，4 位小数） |
| `calc_version` | int | 计算版本，接口默认只返回最新版本 |
| `calc_time` | string | 该值计算时间 `YYYY-MM-DD HH:MM:SS`，用于判断数据新鲜度 |
| `batch_id` | string | 取数批次号，排查数据来源时使用 |

```json
{ "metrics": ["marketing_office_expense"], "total_only": true }
```

```json
{
  "code": 0, "msg": "查询成功", "success": true,
  "data": {
    "period_type": "month", "period_start": "2026-09", "period_end": "2026-09", "total_only": true,
    "totals": [
      { "metric_code": "marketing_office_expense", "metric_name": "营销中心办公费用",
        "excel_code": "EXP-01-a", "period_value": "2026-09", "value": 6871.01, "calc_version": 1,
        "calc_time": "2026-09-27 03:59:42", "org_count": 14 }
    ],
    "items": [], "errors": [],
    "summary": { "metric_count": 1, "item_count": 14, "org_count": 14, "total": 6871.01 }

```

- 不传 `period_start`/`period_end` 时取当前期间；要看多个月趋势就传区间，`totals` 按期间各返回一行。
- 一个指标取一个数：`data.totals[0].value`。
- `metrics` 也可以直接传 Excel 科目编码，例如 `{ "metrics": ["EXP-01-a"], "total_only": true }`，效果与传 `marketing_office_expense` 完全一致。

### 4.6 取数行为约定

1. **只返回存在的行**：某组织某期间没有数据时不会补 0，请按 0 处理。
2. **默认最新计算版本**：同一「指标 × 期间」若多次重算，只返回 `calc_version` 最大的结果。
3. **月指标为累计值**：当日重算的是当月累计数；月数据在次月 1 日补算一次，建议每天 08:00 之后取数。
4. **部分指标不可读不报错**：混入不存在/停用的编码时接口仍返回 `code=0`，这些编码在 `data.errors` 中；若全部不可读则返回 `403`。
5. **限流**：业务接口默认每应用 600 次/分钟，换令牌接口 30 次/分钟；超限返回 `429 / 40103`。
6. **无组织维度的指标**（如 CRM 报价类、出库总量类）：不按组织拆分，返回行 `org_code` 为 `null`、`org_count` 为 `0`；**请求时不要传 `org_codes`**，否则会被过滤成空。

## 6. 错误码与处理

| 业务码 `code` | HTTP | 含义 | 处理建议 |
|---|---|---|---|
| 0 | 200 | 成功 | - |
| 40100 | 401 | 未带令牌 / 令牌无效 / 令牌过期 | 重新换令牌（第 2 节），注意 `Bearer` 后有空格 |
| 40101 | 403 | 应用被停用 / 凭证过期 / IP 不在白名单 | 联系管理员 |
| 40102 | 403 | 指标或层级未授权（如未开通核算维度明细） | 去掉 `level=dept/all` 或联系管理员开通 |
| 40103 | 429 | 超过调用频率 | 按 `msg` 中的建议秒数退避重试 |
| 40104 | 400 | 参数非法（期间格式、跨度超限、指标数超限等） | 按第 4.1 节修正参数 |
| 40105 | 500 | 服务内部错误 | 把响应 `msg` 与请求时间反馈给管理员 |

## 7. 常见问题

1. **`items`/`totals` 为空**：该期间还没算。先用 `GET /open/v1/metrics` 确认编码存在，再联系管理员触发重算。
2. **数值与后台页面不一致**：确认返回的 `calc_version` / `calc_time`；页面重算后需重新请求。
3. **`org_code` 为 `null`**：该行属于未映射到标准组织的机构，仅在未限制组织范围时出现。
4. **要部门/客户明细**：默认只给组织合计，需要管理员在「开放接口 → 接入应用」里开启「核算维度明细」。
5. **想要一次性全量**：把 `period_start`/`period_end` 放到上限（月 36 个）分批取，避免单次请求过大。
