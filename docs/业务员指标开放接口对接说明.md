# 业务员指标开放接口对接说明

> 生成时间：2026-10-09 14:01（**由 `backend/scripts/gen_person_metric_api_doc.py` 从数据库自动生成，请勿手工修改**）
> 对外服务地址：`https://<后台域名>`
> 指标范围：分类「营销中心-业务员」，共 16 个；指标粒度 = **年月 × 业务员**
> 样例期间：2026-09（样例数值为真实结果，可直接用于联调比对）

## 1. 这是什么

本系统是**数据中台 / 指标计算层**：从 CRM 等来源系统取明细，按「年月 × 业务员」算成指标，
再通过开放接口交付给其他系统。调用方只需拿 `app_id` / `app_secret` 换令牌后取数，
**不需要自己拼明细、也不接触业务库**。

对接方需要知道的三件事：

1. **粒度**：每次取数返回的是「某个月 × 某业务员」的指标值，一个业务员一行。
2. **权限**：调用方的接入应用需要开通「业务员明细」权限（`allow_person_detail`），否则 `level=person` 会被拒绝（403）。
3. **合计**：`total_only=true` 只回公司合计；业务员明细用 `level=person`。

## 2. 接入三步

### 2.1 申请接入应用

向平台管理员申请，拿到 `app_id` 与 `app_secret`（密钥仅下发一次，请妥善保存），并确认两件事：

- 已开通**业务员明细**权限（`allow_person_detail`）
- 授权范围（组织 / 指标）是否覆盖你需要的指标

### 2.2 换取访问令牌

```bash
curl -X POST "https://<后台域名>/open/v1/auth/token" \
  -H "Content-Type: application/json" \
  -d '{"app_id":"<你的app_id>","app_secret":"<你的app_secret>"}'
```

```json
{
  "code": 0,
  "msg": "获取令牌成功",
  "data": { "access_token": "eyJ...", "token_type": "Bearer", "expires_in": 7200 }
}
```

### 2.3 取数

```bash
curl -X POST "https://<后台域名>/open/v1/metrics/query" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <access_token>" \
  -d '{
    "metrics": ["STF-13", "STF-10"],
    "period_start": "2026-09",
    "period_end": "2026-09",
    "level": "person",
    "format": "long"
  }'
```

## 4. 请求参数（`POST /open/v1/metrics/query`）

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `metrics` | string[] | 是 | - | 指标标识，可用系统编码或 Excel 科目编码（如 `marketing_person_order_intake_untaxed` / `STF-13`），单次上限 20 个 |
| `period_type` | string | 否 | `month` | 业务员指标均为月指标，保持 `month` |
| `period_start` | string | 否 | 当前月 | 起始期间（含），格式 `YYYY-MM` |
| `period_end` | string | 否 | 同 `period_start` | 结束期间（含）；跨月取数时按月各返回一行 |
| `level` | string | 否 | `org` | **业务员明细必须传 `person`**；`org`=公司合计，`dept`=核算维度明细，`all`=全部 |
| `person_ids` | int[] | 否 | 全部 | 业务员主ID（内部标准人员ID），如 `[139,140]` |
| `person_codes` | string[] | 否 | 全部 | 业务员编码（CRM 用户名），如 `["lixinhui"]` |
| `format` | string | 否 | `long` | `long` 长表（一行一个「指标×业务员×期间」）/ `wide` 宽表（指标做列） |
| `total_only` | bool | 否 | `false` | 只回公司合计（结果在 `totals`，`items` 为空） |
| `include_meta` | bool | 否 | `true` | 是否返回指标口径元信息 |

> 说明：业务员指标没有组织维度，**不要传 `org_codes`**（传了会按组织过滤成空结果）。

| `value` | number | 指标值（保留 4 位小数，单位见指标清单） |
| `calc_version` | int | 计算版本（每次重算递增） |
| `calc_time` | string | 计算时间（北京时间），用于判断数据新鲜度 |

## 8. 口径注意事项（务必阅读）

1. **合计 ≠ 业务员行相加**：平均值类（下推周期）与去重计数类（总客户数、老客户数）
   的公司合计按「Σ分子 ÷ Σ分母」或「客户并集」计算。要合计请用 `total_only=true`，
   不要把 `level=person` 的行直接相加。
2. **期间口径**：接单类取订单创建月；出货类取发货单审核月；报价类取报价日期；
   下推类取 ERP 下推时间；客户列表为**当前快照**（历史期间取重算时点的客户归属）。
3. **业务员归属**：订单/报价类取**下单人 `create_id`**；总客户数取客户表**负责人 `principal_id`**。
4. **缺失即 0**：某业务员某月没有数据时不返回该行，请按 0 处理。
5. **数据刷新**：每日 02:00 同步来源明细、02:30 重算当月；次月 1 日重算上月并结转。
   月数据建议在次月 1 日 08:00 之后再取。

## 9. 错误码

| 业务码 `code` | HTTP | 含义 | 处理建议 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | - |
| 40100 | 401 | 未带令牌 / 令牌无效或过期 | 重新换令牌 |
| 40101 | 403 | 应用停用 / 凭证过期 / IP 不在白名单 | 联系管理员 |
| 40102 | 403 | 未开通业务员明细（`level=person`）等权限 | 联系管理员开通 `allow_person_detail` |
| 40103 | 429 | 超过调用频率 | 按 `msg` 建议秒数退避重试 |
| 40104 | 400 | 参数非法（期间格式、指标数超 20 等） | 修正参数 |
| 40105 | 500 | 服务内部错误 | 反馈 `msg` 与请求时间 |
