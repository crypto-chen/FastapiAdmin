# 客户分析月度指标开放接口对接说明（外部系统）

> 版本：v1.0
> 生成时间：2026-10-14 17:21（**由 `backend/scripts/gen_customer_api_doc.py` 从数据库生成，请勿手工修改**）
> 接口前缀：`/open/v1`（与内部管理端 `/customer/*` 物理隔离，网关只需放行 `/open/**`）
> 对外服务地址：`https://<后台域名>`（开发环境 `http://127.0.0.1:8001`）
> 粒度：**年月 × 客户**（一行一客户一期间），字段口径 = 财务底稿 `CUS-00 ~ CUS-47`
> 样例期间：`2026-09`（calc_version=6，共 21,576 行，样例数值为真实结果，可直接用于联调比对）

---

## 1. 这是什么

本系统是**数据中台 / 指标计算层**：从 CRM、金蝶取明细，按「年月 × 客户」算成客户分析指标，
再通过 `/open/v1/customers` 交付给 BI、数据仓库、CRM/ERP、Excel 插件等外部系统。
调用方只拿 `app_id` / `app_secret` 换令牌后取数，**不需要自己拼明细、也不接触业务库**。

对接方需要知道的三件事：

1. **粒度**：一次取数返回「某个月 × 某客户」的指标值，一个客户一行；另有 1 行合计（`fields.CUS-01` 为空、且 `is_aggregate` 为真）。
2. **权限**：接入应用必须开通 **`allow_customer_detail`**，否则接口返回 403；成本毛利类字段另需 `allow_cost_fields`。
3. **版本**：同一期间可重算多次，`calc_version` 递增；**不传版本取该期间最新版本**，历史版本仍可按 `calc_version` 回溯。

---

## 2. 接入三步

1. **申请接入**：向平台管理员申请，拿到 `app_id`、`app_secret`（密钥只下发一次），并确认：
   - 已开通客户分析查询权限 `allow_customer_detail`（**必须**，否则 403）；
   - 是否需要成本毛利类敏感字段（`allow_cost_fields`）；
   - 是否配置 IP 白名单（`ip_whitelist`）。
2. **换令牌**：`POST /open/v1/auth/token`，拿 `access_token`（默认有效期 7200 秒，过期重换即可）。
3. **拉数据**：带 `Authorization: Bearer <access_token>` 调 `GET /open/v1/customers`。

```bash
# 1) 换令牌
curl -X POST "https://<后台域名>/open/v1/auth/token" \
  -H "Content-Type: application/json" \
  -d '{"app_id":"<你的app_id>","app_secret":"<你的密钥>"}'

# 2) 拉某个期间的客户分析明细（样例期间 2026-09）
curl -X GET "https://<后台域名>/open/v1/customers?period_value=2026-09&page_no=1&page_size=500" \
  -H "Authorization: Bearer <access_token>"
```

## 3. 鉴权与权限

### 3.1 换令牌（client_credentials）

```
POST /open/v1/auth/token
Content-Type: application/json

{ "app_id": "your_app", "app_secret": "******" }
```

```json
{
  "code": 0,
  "msg": "获取令牌成功",
  "data": {
    "access_token": "eyJhbGciOi...",
    "token_type": "Bearer",
    "expires_in": 7200
  },
  "status_code": 200,
  "success": true
}
```

业务接口统一带 `Authorization: Bearer <access_token>`。

> **判断成功看 `code == 0` 或 `success == true`**，不要看 `code` 是否等于 200；真正的 HTTP 状态码在 `status_code` 字段。

建议：令牌过期前 5 分钟主动续期；收到 `401` 时重新换令牌后重试一次。

### 3.2 应用级权限（管理员侧配置）

| 配置项 | 作用 | 默认 |
| --- | --- | --- |
| `allow_customer_detail` | **必须开启**，否则 `/open/v1/customers/**` 全部返回 403 | 关闭 |
| `allow_cost_fields` | 是否允许读取成本毛利类敏感字段（13 个：`CUS-18`、`CUS-21`、`CUS-22`、`CUS-24`、`CUS-25`、`CUS-26`、`CUS-27`、`CUS-28`、`CUS-30`、`CUS-32`、`CUS-36`、`CUS-36-1`、`CUS-38`）；关闭时字段目录与数据都会剔除 | 关闭 |
| `ip_whitelist` | 调用方 IP 白名单（逗号分隔，支持 `192.168.1.*`），不在名单内返回 403 | 空（不限） |
| `rate_limit` | 每分钟最大请求数（换令牌另有固定上限 30 次/分钟） | 600 |
| `token_ttl_seconds` | 令牌有效期（秒），最小 300 | 7200 |

## 4. 接口清单

| 方法 | 路径 | 用途 | 需要令牌 |
| --- | --- | --- | --- |
| POST | `/open/v1/auth/token` | 应用凭证换访问令牌 | 否 |
| GET | `/open/v1/customers/fields` | 字段目录（编码、名称、类型、分组、是否敏感、schema 版本） | 是 |
| GET | `/open/v1/customers` | **客户分析明细拉取（主接口）** | 是 |
| GET | `/open/v1/customers/{customer_code}` | 单客户详情（固定取最新期间 + 最新版本） | 是 |

> 客户维度指标**不在** `/open/v1/metrics/query` 里（该接口的 `level` 只支持 `org` / `dept` / `person` / `all`）。
> 想要「业务员维度的客户类指标」，用 `POST /open/v1/metrics/query` + `level=person`，指标编码见《业务员指标开放接口对接说明》
> （`STF-40` 新客户业绩、`STF-41` 老客户业绩、`STF-47` 总客户数量、`STF-48` 本月下单老客户数量、`STF-49` 复购率）。

## 5. 接口详情

### 5.1 字段目录 `GET /open/v1/customers/fields`

外部系统**先拉字段目录**，再按需拼装自己的表结构；字段增删时 `schema_version` 会变化。

```json
{
  "code": 0,
  "msg": "查询字段目录成功",
  "data": {
    "schema_version": "2026-10-14",
    "fields": [
      {
        "field_code": "CUS-12",
        "field_name": "接单未税",
        "data_type": "number",
        "group": "金额",
        "sensitive": false,
        "excel_code": "CUS-12",
        "source": "CRM",
        "note": "Σ 销售订单未税金额",
        "stored_in": "extra"
      }
    ]
  },
  "status_code": 200,
  "success": true
}
```

| 返回字段 | 说明 |
| --- | --- |
| `schema_version` | 字段集版本（日期串）；变化说明字段集有调整，外部可据此加列/重建表 |
| `field_code` | 字段编码 `CUS-xx`（**外部系统只认这个，不要依赖中文名**） |
| `data_type` | `string` / `number` |
| `group` | 分组：基础、维度、金额、回款、应收、成本、库存、其他 |
| `sensitive` | 是否成本毛利类敏感字段（受 `allow_cost_fields` 控制） |
| `source` | 底稿来源：系统 / CRM / ERP / 财经 / 合同 / 计算 |
| `note` | 口径说明 |
| `stored_in` | `core`（物理列）/ `extra`（扩展区），对外使用可忽略 |

### 5.2 明细拉取 `GET /open/v1/customers`

**请求参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `period_value` | string | 否 | 最新期间（`2026-10`） | 期间 `YYYY-MM`，按所属月份归档 |
| `calc_version` | int | 否 | 该期间最新版本（当前 `4`） | 计算版本，最新版本号随时间回补递增 |
| `customer_code` | string | 否 | - | 客户编码，**模糊匹配** |
| `customer_name` | string | 否 | - | 客户名称，**模糊匹配** |
| `salesman_code` | string | 否 | - | 业务员编码，**精确匹配**（仅供参考筛选，业务字段里出姓名） |
| `order_type` | string | 否 | - | 订单类型，模糊匹配（如 `批量`、`打样`） |
| `product_line` | string | 否 | - | 产品线大类，模糊匹配 |
| `include_aggregate` | bool | 否 | `true` | 是否返回合计行（`is_aggregate=true` 的那一行） |
| `page_no` | int | 否 | 1 | 页码 |
| `page_size` | int | 否 | 500 | 每页条数，**上限 2000** |

> 说明：`order_type` / `product_line` 存的是「多值拼接串」（如 `批量/打样`），按包含关系过滤；
> 因此这两个条件会先在数据库取页、再在应用层过滤，**建议与 `period_value` 一起使用**，避免分页漏行。

**响应**

**排序**：明细行在前、**合计行固定排在结果集最后一行**（先按 `is_aggregate` 升序，再按 `CUS-12` 接单未税降序）。

取合计行的两种做法：

1. 直接翻到最后一页：`page_no = ceil(total / page_size)`（本期样例 total=21,576、page_size=500 → 第 44 页）；
2. 只要合计不要明细时，外部系统按 `data_quality_flag == "aggregate"` 筛出该行即可（`include_aggregate` 必须保持 `true`）。

| 返回字段 | 说明 |
| --- | --- |
| `data.schema_version` | 字段集版本 |
| `data.period_value` / `data.calc_version` | 实际命中的期间与版本（**分页请求之间请带上这两个值，防止重算换版导致翻页串行**） |
| `data.total` | 本次条件下总行数（含合计行；`include_aggregate=false` 时不含） |
| `data.has_more` | 是否还有下一页（等价于 `page_no * page_size < total`） |
| `data.summary` | 期间汇总：`customer_count`（`CUS-43` 客户主档总数）、`order_count`、`intake_untaxed_sum`（`CUS-12`）、`net_shipment_sum`（`CUS-16`）；**当页无合计行时四项均为 `null`** |
| `data.rows[]` | 每行 `{ customer_code, fields }`；**所有 CUS-xx 指标值都在 `fields` 里**，按字段编码取值 |

合计行识别方式：`fields["is_aggregate"] == true`（或 `data_quality_flag == "aggregate"`），该行 `customer_code`、
`CUS-01`、`CUS-02` 都为空串/`null`，中文名只出现在核心列 `customer_name`（值为 `合计`）；其 `CUS-12` / `CUS-16` / `CUS-43` 即公司合计。

字段取值约定：`fields` 里 **47 个 `CUS-xx` 键恒定存在**，该口径本期不产出时值为 `null`（不是缺键、也不是 0），
外部建表请统一按「键存在、值可空」处理。

除 `CUS-xx` 外，`fields` 里还有几个**内部核心列**，可一并使用（样例中为简洁未展开）：

| 核心列 | 说明 |
| --- | --- |
| `customer_code` / `customer_name` | 客户编码 / 名称（与 `CUS-01` / `CUS-02` 同值；合计行为 `null` / `合计`） |
| `is_aggregate` | 是否合计行（`true` 为合计） |
| `order_count` | 接单量（订单条数） |
| `intake_untaxed` / `net_shipment` | 接单未税 / 对外出货净额（与 `CUS-12` / `CUS-16` 同值） |
| `gross_profit` / `contribution_margin` | 毛利 / 边际贡献（**核心列，不受 `allow_cost_fields` 裁剪**，见 §9） |
| `data_quality_flag` | 行类型：`ok` / `ar_only` / `aggregate` |
| `salesman_code` / `salesman_name` | 业务员编码 / 姓名（编码仅供筛选追溯） |
| `period_value` / `calc_version` / `customer_id` / `id` | 期间、版本与内部主键 |

### 6.2 关键口径

| 字段 | 口径 |

| `CUS-12` 接单未税 | Σ 当期有效订单未税金额（内贸 `remove_taxes_freight` + 外贸 `receivable_CNY`，status=384），按客户聚合 |

## 7. 分页、增量与对账

1. **分页**：`page_size` 上限 2000；翻页期间固定 `period_value` + `calc_version`，用 `has_more` 判断结束。
2. **增量**：本接口按「期间 + 版本」全量分页，没有时间戳增量。做法是**期间级替换**：
   - 首次同步：对需要的历史期间逐期拉全量落库；
   - 日常同步：每天拉当月（`period_value` 不传即最新期间），按 `customer_code` 覆盖写入；
   - 月末定稿：拉上月，`calc_version` 变化即视为数据已重算，重新覆盖该期间全量。
3. **对账**（合计行在结果集最后一行，见 §5.2 样例 2）：
   - 明细行 `CUS-12` 求和 = 合计行 `CUS-12` = `summary.intake_untaxed_sum`；本期样例 7913807.89。
   - 明细行 `CUS-16` 求和 = 合计行 `CUS-16` = `summary.net_shipment_sum`；本期样例 4497453.47。
   - 明细行 `CUS-16` ≠ 明细行 `CUS-13` 求和（还含设计服务收入与退货退款），核对时用 `CUS-16`。
   - `summary.customer_count`（`CUS-43`）是客户主档时点总数，**不等于**明细行数，不要拿它做行数校验。
   - `total` 含合计行 → 明细行数 = `total − 1`（`include_aggregate=false` 时 `total` 即明细行数）。
4. **重算节奏**：每天 02:20 重算最近 3 期（含当月，接在订单全链路 02:10 之后）；每月 1 日先结转上月再回补最近 3 期。
   写入按「期间 + 版本」全量替换，外部按 `calc_version` 变化触发覆盖即可，不会读到半量数据。

## 8. 错误码

| `code` | HTTP | 场景 | 处理建议 |
| --- | --- | --- | --- |
| `0` | 200 | 成功 | - |
| `40100` | 401 | 未带令牌 / 令牌过期或失效 / 应用不存在 | 重新换令牌后重试一次 |
| `40101` | 403 | 应用已停用 / 凭证过期 / 未开通 `allow_customer_detail` / IP 不在白名单 | 联系管理员开通或调整配置 |
| `40103` | 429 | 调用频率超限 | 按 `msg` 提示的秒数退避重试 |
| `1` | 422 | 查询参数不合法（如 `page_size` > 2000、`page_no` < 1），`data` 为逐字段校验明细 | 修正参数后重试 |
| `-1` | 500 | 单客户详情：该客户在最新期间没有数据 | 先确认客户编码存在，再取详情 |

  "msg": "应用未开通客户分析查询权限",
  "data": null,

## 9. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 全部接口 403 | 应用未开通 `allow_customer_detail` | 让管理员在开放应用里勾选后重试 |
| 字段目录少了成本毛利字段 | 未开通 `allow_cost_fields` | 按需申请；开通后字段目录与数据同时可见 |
| 未开通 `allow_cost_fields`，但 `fields.gross_profit` / `fields.contribution_margin` 仍有值 | 这两个是核心列，裁剪开关目前只作用于 `CUS-xx` 成本字段 | 需要完全屏蔽时联系管理员评估；对接方入库时按需忽略这两列 |
| 某字段整列为空 | 该字段口径待上游补数据（见 §6 出数行数为 `—`） | 以 0 或空值落库，不要按 0 参与比率分母 |
| `data.summary` 四项全是 `null` | 合计行不在当前页（合计行固定排在结果集最后一行） | 翻到最后一页取，或自己按明细行求和；见 §5.2 |
| 47 个 `CUS-xx` 键都在、但很多值是 `null` | 未产出口径统一以 `null` 占位（键恒定存在） | 按可空列建表；比率类字段遇 `null` 按「无数据」处理，不按 0 |
| 明细行数远大于订单客户数 | 本期行集含「本月无订单但有应收」的客户（`ar_only`） | 按 `data_quality_flag` 过滤：只看订单类用 `ok` |
| 翻页时同一客户出现两次 | 期间被重算，`calc_version` 变了 | 翻页期间固定 `calc_version` |
| `CUS-43` 总客户数在明细行取不到 | 该字段只写合计行 | 取合计行（`is_aggregate=true`）或最后一页的 `summary.customer_count` |
| 单客户详情返回 500 / `code=-1` | 该客户在最新期间没有数据（详情接口不接受 `period_value`） | 先用明细接口按 `customer_code` 确认存在，再取详情 |
