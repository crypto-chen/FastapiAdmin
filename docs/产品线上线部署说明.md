## 0.1 非 Docker（conda / venv 直跑）速查

服务器不是 Docker 时，**在 `backend` 目录下跑一个 Python 脚本就够了**：

```bash
cd /path/to/FastapiAdmin && git pull origin master     # 到 3d3cb74d 或更高

# ① 前端构建并发布（Python 脚本不包含这步）
cd frontend/web && npm install && npm run build && cp -r dist/* <你的 nginx 站点目录>/ && cd ../..

# ② 后端依赖（首次部署 / requirements.txt 有变化时；必须在 backend 下跑）
conda activate <你的环境名>
cd backend && python -m pip install -r requirements.txt && cd ..

# ③ 一键部署（dev 环境；--dry-run 先看会做什么）
cd backend
python scripts/deploy_product_line.py --dry-run
python scripts/deploy_product_line.py --periods 2026-07,2026-08,2026-09
```

脚本依次做 8 步：**备份 → 迁移 → 建来源对象/同步任务 → 建实体/字段/菜单 → 回补取数 → 订单全链路 →
产品线宽表 → 出对接文档 → 自检**，每步打印实际命令与输出，任一步失败即中止。

常用参数：`--env dev`（默认，读 `backend/env/.env.dev`）｜`--periods 2025-01,2025-02`｜
`--skip-backup`｜`--skip-doc`｜`--base-url https://<对外域名>`｜`--dry-run`

要点：

1. **环境文件**：后端读 `backend/env/.env.{ENVIRONMENT}`；dev 用 `.env.dev`，prod 用 `.env.prod`（参照 `backend/env/.env.example` 创建）。
2. **依赖安装位置**：`requirements.txt` 里金蝶 SDK 是相对路径 `./vendor/kingdee.cdp.webapi.sdk-8.2.0-py3-none-any.whl`，`pip install -r requirements.txt` **必须在 `backend/` 目录下执行**。
3. **重启后端**：新增的同步任务要重启一次进程才会进调度器（脚本结束时会提醒）。
4. **备份**：脚本用 `mysqldump` 备份到 `~/fastapiadmin_backup_*.sql`；PATH 里没有 `mysqldump` 或 `.env` 里没配 `DATABASE_PASSWORD` 时会跳过并提醒（
   `--skip-backup` 可显式跳过）。
5. **幂等**：脚本可反复跑；产品线宽表按 `calc_version` 追加，**不覆盖历史版本**。

## 12. 回滚

1. **接口下线**（最快）：`UPDATE open_client SET allow_product_line_detail = 0 WHERE app_id='...';` —— 开放接口立即 403，前端可隐藏菜单。
2. **代码回滚**：恢复上一版本代码 → `./deploy.sh`（或 `docker compose up -d --force-recreate backend`）。新增表/列保留不影响旧代码。
3. **数据库回滚**：用第 1 步备份恢复；或 `docker compose exec backend python -m alembic downgrade e2d66304120f`（回退 `open_client` 开关列）。

## 13. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 启动报 `Unknown column 'ship_qty'` / 表不存在 | 迁移没应用：`docker compose exec backend python main.py upgrade --env=prod` |
| 建表报 `(1071, 'Specified key was too long; max key length is 1000 bytes')` | 唯一键 `uq_dwd_product_line_key` 用了过宽的列：老版本/非 DYNAMIC 行格式的 InnoDB 索引键上限只有 767/1000 字节。当前模型已收到 `product_line_code VARCHAR(64)` + `sku VARCHAR(64)`（≈580 字节）。若库里已有宽表，跑 `python scripts/fix_product_line_schema.py --apply` 自动收窄 |
| `alembic heads` 出现 2 个 head / `Multiple head revisions` | 仓库里有本机自动生成的重复迁移（不在 git 中）。见 `python scripts/fix_product_line_schema.py` 输出与部署脚本的前置自检提示 |
| 启动报 `Multiple head revisions are present for given argument 'head'; ... <rev1>, <rev2>` | dev 自动迁移生成了**未跟踪**的重复迁移，`upgrade head` 直接失败导致后端起不来。跑 `python scripts/fix_alembic_heads.py --apply`：先删未跟踪 head（会打印其 DDL 便于核对）→ 仍有多个则 merge → 清理失效版本号（清空时自动 stamp）→ `upgrade heads`。启动端已改为 `upgrade heads` 并在多头时自动合并 |
| 迁移报 `(1050, "Table 'dwd_cost_bill_workorder' already exists")` | 表早前被哨兵迁移建好了，而 `c057b1112026` 的建表语句从没成功执行过。迁移已改为幂等（建表前 `has_table` 判断、外键/索引逐项判断），直接重跑 `python scripts/fix_alembic_heads.py --apply` 即可对齐，不会重复建表 |
| 手工 `alembic stamp` 后报 `Unknown column` | `stamp` 只改版本号、不执行 DDL。用 `python scripts/fix_product_line_schema.py --apply` 补齐建表/加列 |
| `Table 'xxx.dwd_cost_bill_workorder' doesn't exist` | 迁移 `c057b1112026` 的 DDL 没执行。`sync_cost_bill_workorders.py` / `run_product_build.py` 已内置建表兜底：直接重跑脚本即可，首行会打印「补建缺失表：...」；随后建议再跑一次 `python -m alembic upgrade head` 对齐版本号 |
| 成本计算单先跑过 `--mode light`，再跑 `--mode full` 会跳过已有行 | 已修复：full 模式会把 `extra.mode != full` 的旧行按工单重抓覆盖（行数不变，唯一键不冲突） |
| 菜单里看不到「产品线分析」 | `seed_product_module.py` 没跑；或角色未授权（重跑脚本会补），前端需重新登录刷新菜单 |
| 页面 404 / 空白 | 前端 `dist` 没更新（第 3 步） |
| `run_product_build.py` 报「没有订单批次」 | 订单全链路还没建：先跑第 7 步 ② |
| 产品线宽表 0 行 | 该期间无订单批次；先确认 `dwd_order_full_chain` 有该期间数据 |
| 产品线大类出现「未分类」 | 订单行的型号既不在型号字典、也没有产品系列 ID（正常占比 <0.2%） |
| 出货数量列大量为空 | 该期间订单尚未发货（如当期最后一个月），或发货明细批次没回补（第 7 步 ①） |
| 开放接口 403「应用未开通产品线分析查询权限」 | 第 8 步开关没开 |
| 同步任务没按点跑 | 重启后端让调度器重挂：`./deploy.sh restart` |

### 14.10 conda 常见坑

| 现象 | 原因 / 处理 |
| --- | --- |
| `No module named k3cloud_webapi_sdk` | 金蝶 SDK 没装（用 wheel 装）：`cd backend && python -m pip install ./vendor/kingdee.cdp.webapi.sdk-8.2.0-py3-none-any.whl` |
| `pip install -r requirements.txt` 报找不到 wheel 文件 | 没在 `backend/` 目录下执行（requirements.txt 用的是相对路径 `./vendor/...`） |
| 脚本跑通了但调度器没跑新任务 | 后端进程没重启（§14.8） |
| `main.py upgrade` 报连接失败 | `ENVIRONMENT` 不对（读的是 `backend/env/.env.$ENVIRONMENT`），或 `.env.prod` 里 `DATABASE_HOST` 仍是 localhost 而库里在另一台 |
| 前端页面 404 | nginx 站点目录没更新（§14.5），或后端 `WEB_URL` / `ROOT_PATH` 与反代前缀不一致 |
| 定时任务时间不对 | 服务器时区不是 Asia/Shanghai：`timedatectl set-timezone Asia/Shanghai` |
