# 平台渠道分析指标开放接口对接说明

> 面向第三方系统（BI / 报表 / 数据中台）：只读拉取「平台 × 店铺 × 期间」的接单、
> 出货、退货、净额、结算收入指标。数据由零售订单与售后单实时汇总，不落缓存。

服务地址：`http://120.237.174.243:6479`
接口前缀：`/open/v1`

## 1. 指标清单

接口返回的每个 `items[]` 行 = 「期间 × 店铺」；`total` 是同口径汇总。字段与编码一一对应：

### 1.1 维度

| 编码 | 指标 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| PLT-00 | 期间 | `period_value` | string | `YYYY-MM`，订单归属期间 |
| PLT-01 | 平台 | `platform` | string | 由店铺站点归一：天猫 / 京东 / 拼多多 / 抖音 / 小红书 / 1688 / 其他 |
| — | 平台原值 | `shop_site` | string | 聚水潭返回的原始站点（如「淘宝天猫」），便于对账 |
| PLT-02 | 店铺 | `shop_name` | string | 店铺名称 |
| PLT-03 | 店铺编号 | `shop_id` | number | 聚水潭 shop_id |

### 1.2 数量

| 编码 | 指标 | 字段 | 类型 | 口径 |
| --- | --- | --- | --- | --- |
| PLT-04 | 订单数 | `order_count` | number | 期间内有效订单（排除 Delete，含取消单） |
| PLT-05 | 已发货单数 | `shipped_order_count` | number | 订单状态 = `Sent` |
| PLT-06 | 取消单数 | `cancelled_order_count` | number | 订单状态 = `Cancelled` |

### 1.3 金额（元，保留 2 位小数，已去税）

| 编码 | 指标 | 字段 | 口径 |
| --- | --- | --- | --- |
| PLT-08 | 接单未税 | `intake_untaxed` | 订单买家实付 ÷ 1.13（含后续取消的单） |
| PLT-09 | 货物出货未税 | `shipment_untaxed` | **已发货订单**金额 ÷ 1.13（订单已发货即算货物出货） |
| PLT-10 | 取消未税 | `cancelled_untaxed` | 取消单金额 ÷ 1.13，负数；已并入 PLT-11，单列供对账 |
| PLT-11 | 退货退款 | `return_untaxed` | -(取消单金额 + 发货后售后实退) ÷ 1.13，负数 |
| PLT-12 | 对外出货净额 | `net_shipment_untaxed` | `PLT-09 + PLT-11` |
| PLT-13 | 营销结算收入10% | `settlement_income_untaxed` | `PLT-12 × 10%`（比例可配） |
| PLT-23 | 总部分摊 | `hq_allocation_untaxed` | `PLT-13 × 4%`（比例可配，符号与 PLT-13 一致） |
| — | 发货后售后未税 | `refund_untaxed` | 只含发货后申请的售后实退，负数；PLT-11 = PLT-10 + 该字段 |

### 1.4 比率

| 编码 | 指标 | 字段 | 类型 | 口径 |
| --- | --- | --- | --- | --- |
| PLT-37 | 退货率 | `return_rate` | number | `|PLT-11| ÷ PLT-12`，小数（0.2 = 20%）；PLT-12 ≤ 0 时改用 PLT-09 |
| PLT-38 | 客单价 | `avg_order_value` | number | `PLT-08 ÷ 有效订单数`（订单数 - 取消单数），元/单 |

### 1.5 本接口不提供

`PLT-03 运营人员`、`PLT-04 产品线大类`、`PLT-05 SKU`、平台费/推广费/快递费/人工成本等，
需要 CRM 人员映射、ERP 商品字典或财务录入，不在本接口范围。

完整 44 个平台指标（含 7 个待确认、20 个待做）见
`docs/平台店铺分析指标对接方案.md` 第 3 节清单；本接口只返回已实现（现用可出）的字段。
新增指标上线后，用 4.1 的配置化接口即可读到，不需要改你们的代码。

金额单位：元；税率默认 13%、结算比例 10%、总部分摊 4%，由我方配置，调用方不需要再折算。

## 2. 接入准备

由我方在「系统管理 → 开放接口应用」创建应用，提供：

| 项 | 说明 |
| --- | --- |
| `app_id` | 应用标识（对外唯一 ID） |
| `app_secret` | 应用密钥，**只在创建/重置时显示一次** |
| 平台渠道分析开关 | 必须开启「平台渠道分析」，否则接口返回 403 / `40102` |
| IP 白名单（可选） | 逗号分隔，支持 `10.0.0.*` 通配；留空不限制 |
| 限流 | 默认 600 次/分钟，可在应用上调整 |

## 3. 获取访问令牌

```
POST /open/v1/auth/token
Content-Type: application/json
```

```json
{"app_id": "your_app_id", "app_secret": "your_app_secret"}
```

响应：

```json
{
  "code": 0,
  "msg": "获取令牌成功",
  "data": {"access_token": "eyJhbGciOi...", "expires_in": 7200},
  "success": true
}
```

- 令牌有效期默认 7200 秒，过期后重新获取即可；建议缓存并在到期前 5 分钟刷新；
- 换令牌接口单独限流 30 次/分钟，不要每次业务请求都换；
- 应用停用或密钥重置后，旧令牌立即失效（401）。

## 4. 查询平台渠道分析指标

```
GET /open/v1/retail/platform/analysis?period_value=2026-10&platform=天猫&shop_id=900001
Authorization: Bearer <access_token>
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `period_value` | 否 | 期间 `YYYY-MM`；不传返回全部期间 |
| `platform` | 否 | 平台（归一值：天猫/京东/拼多多/抖音/小红书/1688/其他） |
| `shop_id` | 否 | 店铺编号；不传返回全部店铺 |

响应（节选）：

## 4.1 按指标配置返回（新增指标自动出现）

固定字段接口（第 4 节）字段名是约定的；如果我们在管理端新增了平台指标，
可用下面这个「配置化」接口，它的列就是当前启用的指标定义：

```
GET /open/v1/retail/platform/metrics?period_value=2026-10&aggregate_level=platform
Authorization: Bearer <access_token>
```

| 参数 | 说明 |
| --- | --- |
| `period_value` | 期间，缺省=全部 |
| `platform` / `shop_id` | 过滤平台 / 店铺 |
| `aggregate_level` | `detail` 店铺明细 / `platform` 平台小计 / `all` 全部 |
| `page_no` / `page_size` | 分页，默认 1 / 500 |

响应：`columns` 是指标定义（编码、名称、分组、类型、单位、口径），`items` 的键就是指标编码：

```json
{
  "columns": [
    {"field_code": "PLT-01", "field_name": "平台", "data_type": "string", "group": "维度"},
    {"field_code": "PLT-12", "field_name": "对外出货净额", "data_type": "number", "group": "金额", "unit": "元"}
  ],
  "items": [
    {"PLT-00": "2026-10", "PLT-01": "天猫", "PLT-04": 52, "PLT-12": -192.48}
  ],
  "summary": {"net_shipment_sum": -192.48, "return_rate": 1.6416}
}
```

调用方按 `columns` 动态渲染即可，我方新增指标不需要你们改代码。

## 5. 错误码

| 业务码 | HTTP | 含义 | 处理 |
| --- | --- | --- | --- |
| `0` | 200 | 成功 | — |
| `40100` | 401 | 未带令牌 / 令牌无效或过期 | 重新换令牌 |
| `40101` | 403 | 应用停用、过期、IP 不在白名单 | 联系我方核对应用配置 |
| `40102` | 403 | 应用未开通「平台渠道分析」 | 联系我方在开放接口应用中开启 |
| `40103` | 429 | 超过调用频率 | 降低频率或按 `Retry-After` 重试 |
| `40104` | 400 | 参数非法（期间格式等） | 修正参数 |

判断成功请看 `code == 0`，不要只看 HTTP 200。

## 6. 调用示例

curl：

```bash
TOKEN=$(curl -s -X POST "http://120.237.174.243:6479/open/v1/auth/token" \
  -H "Content-Type: application/json" \
  -d '{"app_id":"your_app_id","app_secret":"your_app_secret"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['data']['access_token'])")

curl -s "http://120.237.174.243:6479/open/v1/retail/platform/analysis?period_value=2026-10" \
  -H "Authorization: Bearer $TOKEN"
```

Python：

```python
import requests

BASE = "http://120.237.174.243:6479"
APP_ID, APP_SECRET = "your_app_id", "your_app_secret"

token = requests.post(
    f"{BASE}/open/v1/auth/token",
    json={"app_id": APP_ID, "app_secret": APP_SECRET},
    timeout=10,
).json()["data"]["access_token"]

resp = requests.get(
    f"{BASE}/open/v1/retail/platform/analysis",
    params={"period_value": "2026-10"},
    headers={"Authorization": f"Bearer {token}"},
    timeout=30,
).json()
if resp["code"] != 0:
    raise RuntimeError(resp)
rows = resp["data"]["items"]
```

## 7. 常见问题

1. **403 且 code=40102**：应用没开「平台渠道分析」开关。管理端「开放接口应用 → 编辑」打开即可，令牌不用重换。
2. **出货金额为 0**：当期没有 `Sent` 状态订单，或订单金额字段为空；先看 `shipped_order_count`。
3. **退货率大于 100%**：退货（含取消）大于净出货，多见于取消单集中在某店铺；属正常业务口径。
4. **期间对不上财务报表**：本接口以订单/售后归属期间（`YYYY-MM`）为准，不是平台结算周期。
5. **调用被限流**：默认 600 次/分钟；批量拉多期间请在应用上提高限流或改为按期间分页取。
6. **`platform` 全是「其他」**：店铺主数据还没同步。执行 `python scripts/sync_jushuitan_shops.py`，
   或在「零售订单同步」页点「同步店铺」后重试。

## 8. 审计

每次调用都会写入「开放接口调用日志」：应用、路径、参数（脱敏）、业务码、HTTP 状态、
耗时、调用方 IP，可在管理端「开放接口 → 调用日志」按时间与应用筛选。
