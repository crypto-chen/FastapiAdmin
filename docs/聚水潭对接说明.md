# 聚水潭对接说明（零售出库未税总金额 · 月度）

## 1. 用到的接口

| 项 | 值 |
| --- | --- |
| 接口 | `/open/orders/out/simple/query`（销售出库查询，文档 docType=8 & docId=34） |
| 正式地址 | `https://openapi.jushuitan.com/open/orders/out/simple/query` |
| 测试地址 | `https://dev-api.jushuitan.com/open/orders/out/simple/query` |
| 请求方式 | `POST`，`application/x-www-form-urlencoded;charset=UTF-8` |

公共参数：`app_key`、`access_token`、`timestamp`(秒)、`charset=utf-8`、`version=2`、`biz`、`sign`。
业务参数全部放在 `biz`（JSON 字符串）里。

## 2. 关键取数条件

```json
{
  "status": "Confirmed",
  "date_type": 2,
  "modified_begin": "2026-08-01 00:00:00",
  "modified_end": "2026-08-31 23:59:59"
}
```

- `status=Confirmed` → **出库状态=已出库**（`WaitConfirm` 待出库 / `Delete` 作废 / `Cancelled` 取消）。
- `date_type=2` → 按**出库时间** `io_date` 过滤（`0` 是修改时间）。
- **时段间隔不能超过 7 天**，代码里按 7 天自动分段；`page_size` 最大 50，自动翻页并按 `io_id` 去重。
- 频率限制：并发 5 次/秒、100 次/分钟；超限返回 `code=199/200`，客户端自动退避重试（请求间隔 ≥ 0.62s）。

## 3. 未税总金额怎么来

接口**不返回税额字段**，返回的是含税口径金额。因此：

```
未税总金额 = Σ含税金额 / (1 + 税率)
```

- 取数口径 `amount_source`：`items.auto`（默认，推荐）/ `items.sale_amount` / `items.buyer_paid_amount`（买家实付）/ `items.seller_income_amount`（卖家实收）/ `order.pay_amount`（应付金额，**不要用**，见下）。
- 税率不填（0）时，未税金额 = 接口金额本身。
- 如果贵司口径是「接口金额即为未税」，把 `tax_rate` 设为 0 即可，无需改代码。

### 为什么默认口径是 `items.auto`（实测数据，2026-08）

淘系/拼多多平台规则屏蔽价格字段，导致**单一口径必然漏数**：

| 口径 | 含税金额 | 未税(13%) | 有金额的单数 |
| --- | ---: | ---: | ---: |
| `order.pay_amount`（应付金额） | 47,936.38 | 42,421.58 | 135 / 1947 |
| `items.sale_amount`（明细金额） | 47,936.38 | 42,421.58 | 135 / 1947 |
| `items.buyer_paid_amount`（买家实付） | 471,289.14 | 417,070.04 | 1532 / 1947 |
| `items.seller_income_amount`（卖家实收） | 471,884.87 | 417,597.23 | 1532 / 1947 |
| **`items.auto`（兜底合并）** | **519,225.52** | **459,491.61** | 1667 / 1947 |

规律：国内店铺（淘宝/天猫/1688）只有 `buyer_paid_amount`/`seller_income_amount` 有值，
跨境与自建站店铺（速卖通、独立站、国际站）只有 `sale_amount` 有值，两组互斥。
`items.auto` = 每个明细行内按 `sale_amount → buyer_paid_amount → seller_income_amount`
取第一个非零值，因此两类店铺都能覆盖。兜底顺序可用 `auto_fields` 调整，例如把卖家实收提前：

```bash
python scripts/seed_jushuitan_metric.py ... --auto-fields seller_income_amount,buyer_paid_amount,sale_amount
```

另有约 280 单（1947 − 1667）三个金额字段都为空，多为赠品/线下/无金额单据，需要业务侧确认是否计入。

## 5. 跑通顺序

```bash
cd backend

# 1) 用授权凭据直连自检（不写库）
python scripts/jushuitan_check.py --app-key <ak> --app-secret <as> --access-token <token> --period 2026-08 --tax-rate 13

# 2) 落库：连接 + 来源系统/对象 + 同步任务（每月 1 日 02:00）+ 指标定义
python scripts/seed_jushuitan_metric.py --app-key <ak> --app-secret <as> --access-token <token> --tax-rate 13

# 3) 算某个月的指标（首次会自动补该期间的同步批次）
python scripts/run_metric_calc.py --code retail_outbound_untaxed_amount --period 2026-08
```

`app_secret` 与 `access_token` 落库前用 `CryptoUtil`（Fernet）加密，接口只返回 `has_secret`/`has_token`。

## 6. 注意事项

- 淘系、拼多多平台单据的**价格类字段不下发**（文档原文），这些平台的出库单金额会是 0，需要走奇门/方舟另行对接。
- 分销+订单、线上发货订单不产生销售出库单，取不到数属正常。
- 部分或全部取消：`Delete`（发货前作废）、`Cancelled`（发货后撤销）不计入已出库。
- 按时间翻页存在数据变动导致漏单的可能，文档推荐 `start_ts` 增量方式；月度指标场景已用「7 天分段 + 出库时间」控制影响，如需严格一致可再切 `start_ts`。

## 7. 常见错误码

| code | 含义 | 处理 |
| --- | --- | --- |
| 10 | 无效签名 | 核对 `app_secret` 与 `app_key` 是否配对 |
| 100 | access_token 超时 | 重新授权拿新 token |
| 110 | IP 不在白名单 | 报错信息里会给出出口 IP，加到开放平台后台「应用详情 - IP白名单」；换机房后要同步更新 |
| 140 | 参数不符合规范 | 也可由 `app_key` 无效引起；确认用的是正式环境地址 `openapi.jushuitan.com` |
| 199 / 200 | 并发（5/秒）、频次（100/分钟）超限 | 客户端已自动退避重试，无需处理 |

排查顺序建议：先 `python scripts/jushuitan_check.py ... --period <上月>` 直连自检，再落库跑指标。

## 8. 调度与期间结转

| 时间 | 动作 | 说明 |
| --- | --- | --- |
| 每天 02:00 | 聚水潭同步（`0 0 2 * * ?`） | 按**当月**出库时间拉取，批次落到 `meta_sync_run` |
| 每天 02:30 | 指标批次重算当期（`metric/schedule.py` + `metric/batch.py`） | 按依赖分层重算**当月**累计值，写入新的 `calc_version` |
| 每月 1 日 02:30 | 上期结转 | 先**强制重拉**上月批次，再重算上月 |

为什么必须有「上期结转」：月指标的当月值最后一次刷新发生在月末 02:30，之后当月不再重算；
若不在次月 1 日补算，**月末最后一天白天的出库单会永久缺失**。结转逻辑见
`engine.refresh_period_batches()`（与 `_ensure_period_batches` 不同，它不判断「已有批次就复用」）。

指标之间有依赖（如汇总/比率指标引用组成指标），批次任务按 `metric_def.measures` 声明的依赖
**拓扑分层**执行：组成指标所在层先跑、依赖它的派生指标后跑，同层并发。运行期还会校验组成指标
「当天已算过」，不满足就先补算（`engine._ensure_component_values`）。
查看当前分层顺序：`python scripts/check_metric_deps.py`。

手动回补任意历史月份：

```bash
python scripts/run_metric_calc.py --code retail_outbound_untaxed_amount --period 2026-01
```

该命令会在缺少该期间批次时自动补拉数据，因此历史月份可以逐个补齐。
