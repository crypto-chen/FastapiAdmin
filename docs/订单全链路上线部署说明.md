# 订单全链路上线部署说明（开发环境 → 服务器）

> 适用：把开发环境已完成的**订单全链路（宽表 + 开放接口 + 管理端页面）**部署到服务器。
> 提交：`7ece6dcf`（feat(order): 订单全链路宽表 + 开放接口 + 管理端页面），共 25 个文件。
> 部署形态：Docker Compose（`deploy.sh` + `docker/`）；非 Docker 见第 12 节。
> 执行顺序：**备份 → 传代码 → 迁移 → 建元数据与菜单 → 回补数据 → 重启 → 校验 → 开对接权限**。

**新增的表与列**

| 对象 | 说明 |
| --- | --- |
| 表 `dwd_order_full_chain` | 订单全链路宽表（一行一单，`order_number + calc_version` 唯一） |
| 表 `dwd_order_build_run` | 构建批次记录（版本、订单数、质量统计） |
| 列 `open_client.allow_order_detail` | 是否允许查订单明细（默认关，**必须开**否则 403） |

| 列 `meta_standard_field.excel_code` | 标准字段的指标编码（ORD-xx） |

## 6. 回补订单全链路数据（最耗时的一步）

```bash
cd /path/to/FastapiAdmin/docker

# 全量：按期间重拉各来源批次 → 构建宽表（首次部署用这个）
docker compose exec backend python scripts/run_order_build.py --all --refresh

# 只补某几个月
docker compose exec backend python scripts/run_order_build.py --period 2026-08,2026-09 --refresh
```

要点：

- `--refresh` 会先按期间重拉 6 个来源（CRM 订单明细内贸/外贸、发货明细内贸/外贸、退款明细、金蝶生产订单），
  再构建；首次部署**务必带 `--refresh`**，否则服务器上没有来源批次会直接报错。
- 覆盖期间：**2024-10 ~ 当前月**（取决于服务器上 CRM/金蝶能取到的数据）。
- 耗时：25 个期间约 **5~15 分钟**（取决于 CRM/金蝶响应速度），可分批跑。
- 每期结束会打印：`期间 2026-09 版本 v1：订单 1419 张，关联生产订单 1040 张，成本缺失 149 张`。

## 11. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端起不来，日志报 Redis 连接失败 | Redis 未启动/未就绪 | 确认 `docker compose ps` 里 redis 是 healthy |
| 构建报「没有 CRM 订单明细批次」 | 没带 `--refresh`，或该期间 CRM 无数据 | 加 `--refresh` 重跑 |
| 接口返回 403 `40101` | 应用没开 `allow_order_detail` | `UPDATE open_client ...` 打开 |
| 接口返回 401 | 令牌过期 / IP 不在白名单 | 重新换令牌；核对 `ip_whitelist` |
| 页面打不开，路由警告「找不到组件」 | 前端未重新构建 | 重新 `pnpm build` 并清缓存刷新 |
| 客户名/业务员姓名为空 | 该期间 CRM 批次缺 `customer`/`create_id` 字段 | 见第 13 节数据边界 |

**核心计算口径**

```
标准单位成本 = (材料费 + 加工费) ÷ 订单数量
标准材料成本 = 材料费 ÷ 订单数量
入库数量     = 生产订单「整机」分录的合格入库数（不是各分录求和）
毛利扣减成本 = 标准单位成本 × 入库数量
订单毛利     = 净出货 − 毛利扣减成本
订单边际贡献 = 净出货 − 标准材料成本 × 入库数量
是否准时     = 实际交期 ≤ 预定交期 ? 准时 : 超时
```
