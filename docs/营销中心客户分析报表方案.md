# 营销中心客户分析报表 · 建设方案（v0.1 草案，待确认）

> 目标：按 **年月 × 客户** 统计「营销中心客户分析指标」（Excel 底稿编码 CUS-00 ~ CUS-43）。
> 数据来源：CRM `/hs` 系列接口 + 金蝶 K3Cloud + 本系统已有的订单全链路宽表与公司口径指标。
> 交付形态：**本系统作为指标计算层，产出后经开放接口 `POST /open/v1/metrics/query` 供外部调用**（不自建业务报表）。
> 本文所有「实测」结论来自 2026-10-14 直连探针，命令见 §9。

---

## 0. 一句话结论

平台的指标引擎、订单全链路宽表、117 个公司口径指标都能复用；**唯一缺的是「客户」这一维度**。
44 个字段里：

| 结论 | 项数 | 说明 |
| --- | --- | --- |
| ✅ 现有接口/表 + 客户维度聚合即可 | 12 | 客户编码/名称/地区/贸易类型/业务员/SKU、应收余额、逾期应收、毛利、总客户数、下单频次 |
| ⚠️ 需新增取数类型、映射或派生 | 27 | 接单 / 出货 / 设计费 / 退货 / 净额、各项率、账龄四档、边际贡献与结算收益分摊、复购率、客单价、创建时间 |
| ⛔ 缺来源或缺口径 | 5 | 信用等级（财经）、实际库存、库存周转天数、客户层级、行业 |
| ⏸ **待定（口径未定，本期不做）** | 3 | **回款、回款及时率、订金回款比例**（2026-10-14 财务确认待定） |

> **口径已定稿（2026-10-14 财务给定）**：43 个有效 CUS 编码（CUS-34、CUS-39 已划掉）
> + 4 个待定字段（创建时间 / 客户层级 / 行业 / 下单频次），逐项来源与公式见 §4；
> 回款相关 3 项（CUS-18/19/20）本期挂起。

**关键前置结论（实测）**：`/hs/customer/getCusotmerList` 就是**客户主档**接口
（全量 24,986 条，每行 4 个字段：`principal_id, id, name, number`），
支持 `principal_id`（逗号分隔）与 `name`（精确匹配）过滤；**客户类型 / 行业 / 客户层级 /
信用等级 / 账期不在它返回的字段里**。好消息是订单明细 `/hs/order/orderAnalyze` 目前
**完整返回 142 个字段**（含 `customer_category`、`collection_term`、`region`、`product_series`、
`product_model`、`order_type`、`design_cost` 等），所以大部分客户属性可以直接从订单行取，
**不必等客户档案接口**；而「无订单客户」仍需以客户主档为底表（见 §1.1）。

### 1.1 客户主档接口 `/hs/customer/getCusotmerList`（2026-10-14 实测）

| 项 | 实测结果 |
| --- | --- |
| 返回内容 | **客户主档全量快照**，24,986 行 |
| 字段 | `principal_id`（客户所属业务员）、`id`（客户ID）、`name`（客户名称）、`number`（客户编号） |
| 支持的过滤 | `principal_id=23,15`（逗号分隔多值，返回 329 行）、`name=江西精致能源技术有限公司`（精确匹配，返回 1 行） |
| 不支持的参数 | `id` / `number` / `keyword` / `page` / `limit` / `status` 均被忽略（仍返回全量 24,986 行）→ **无分页** |
| 时间参数 | 无（永远是当前快照），已登记来源对象 + 任务 73，每周一 02:00 全量同步 |

**对客户分析的三个用法**：

1. **客户维度底表**：客户维度不只用「期内有订单的客户」，还要能带上零订单客户
   （CUS-43 总客户数、CUS-40 复购率分母、下单频次分母都依赖它）。
2. **主键归一**：`id` ↔ `orderAnalyze.customer` ↔ `number` ↔ 宽表 `customer_number`
   （样例：`id=8718` / `20210719-014119`），三处口径一致、可直接关联。
3. **缺失属性的唯一登记点**：CUS-03/06 及「客户层级 / 行业 / 创建时间」如果要在系统内补，
   **在这条路由上补字段最省事**——它是现成的来源对象，元数据同步按 `rows_json` 存行、
   加字段零代码改动（补完字段重跑一次同步即可）。

## 2. 本次新增的技术改动点（4 个）

1. **存储**：`metric_value` 增加 `customer_id` / `customer_code` / `customer_name` + 索引
   （迁移参照 `2026_10_09_1130_d81f6c2a7e35.py` 加 `person_code/person_name` 的写法）。
2. **计算**：引擎新增 `group_by = customer`，以及客户维度取数类型
   `crm_customer_amount`（订单明细）、`crm_customer_shipment`（发货明细）、
   `metric_ratio_customer`（分子/分母都是客户维度指标，按客户分别相除）；
   客户主键统一用 **CRM `customer`（客户ID）**，编码用 `customer_number`、名称用客户列表 `name`。
3. **对外输出**：开放接口 `level` 增加 `customer`；新增 `customer_codes` 过滤、
   `allow_customer_detail` 应用权限、返回字段 `customer_id/customer_code/customer_name`、
   `summary.customer_count`；**取合计继续用 `total_only=true`**（去重计数与比率不能按行相加）。
4. **新数据源**：登记 1 个来源对象（应收账龄按档取数，见 §4.2）；
   金蝶收款单 `AR_ReceiveBill` 因 CUS-18~20 挂起而**暂缓登记**（实测已可用，需要时随时接）。

> 与「业务员分析」的改造完全同构，工作量可参照：P0 约 5~6 个工作日。

### 2.1 与「营销中心业务员指标」的对照（同一套指标方案，只是换个维度）

结论：**是同一套做法**——客户指标同样走「指标定义（`metric_def`）+ 取数类型 + `metric_value` + 开放接口」，
只是新增一个 `customer` 维度。差异只有一处：业务员维度当年是**预留列**（`metric_value.person_id` 已存在），
客户维度需要**新建列 + 迁移**。

| 环节 | 营销中心业务员指标（已上线，STF） | 客户分析指标（本次，CUS） |
| --- | --- | --- |
| 指标定义 | `metric_def`，`category=营销中心-业务员`，`excel_code=STF-xx` | 同表，`category=营销中心-客户`，`excel_code=CUS-xx` |
| 指标命名 | `marketing_person_*` | `marketing_customer_*` |
| 注册脚本 | `scripts/seed_crm_person_metrics.py` | 新建 `scripts/seed_crm_customer_metrics.py`（照抄结构） |
| 取数类型 | `crm_person_amount` / `crm_shipment_person_amount` / `crm_order_push_person` / `crm_quote_person` / `metric_ratio_person` | 新建 `crm_customer_amount` / `crm_customer_shipment` / `metric_ratio_customer`；账龄加 `ar_aging_bucket_amount` |
| 结果维度 | `metric_value.person_id / person_code / person_name` | `metric_value.customer_id / customer_code / customer_name`（**需迁移新建**） |
| 结果粒度 | 期间 × 业务员（一行一人） | 期间 × 客户（一行一客户） |
| 对外接口 | `POST /open/v1/metrics/query` + `level=person` + `person_codes` + `allow_person_detail` | 同接口 + `level=customer` + `customer_codes` + `allow_customer_detail` |
| 对接文档 | `scripts/gen_person_metric_api_doc.py` →《业务员指标开放接口对接说明》 | 新建 `gen_customer_metric_api_doc.py` →《客户指标开放接口对接说明》 |
| 内部核对页 | 指标结果页层级多「业务员明细」，表格多一列业务员 | 多「客户明细」层级 + 一列客户 |
| 调度 | 每日 02:30 重算当月，每月 1 日重算上月 | 完全复用，不改 |

## 3. 数据流（客户维度）

```
CRM /hs 系列（按月取，type=1 内贸 / type=2 外贸）
  ├─ orderAnalyze      订单主表（142 字段：客户、类型、账期、产品线、SKU、订单类型、金额、成本）
  ├─ orderShipments    发货明细（order_number, send_qty, price, qty）
  ├─ getReturnOrderDetail 退货退款（number, account, create_id）
  └─ getCusotmerList   客户主档全量快照（principal_id, id, name, number）
金蝶 K3Cloud
  ├─ GL_RPT_AccountBalance  科目 1122 应收账款 → 客户应收余额（明细=往来单位）
  ├─ AR_AgingAnalysis       应收账龄分析表 → 逾期 / 账龄 30-60-90-90+
  ├─ AR_ReceiveBill         收款单 → 回款（实测可用；**本期挂起**，见 §4 待定三项）
  └─ HS_INOUTSTOCKSUMMARYRPT 存货收发存汇总表 → 库存
        ↓
客户主键归一：customer_id → customer_number / customer_name（客户主档）
客户维度聚合：group_by = customer（金额、订单数、去重客户数、比率）
        ↓
metric_value（period_value, customer_id, customer_code, customer_name, value）
        ↓
POST /open/v1/metrics/query  level=customer  → 长表 / 宽表 / 合计
```

## 8. 验收标准

1. **对账通过**：Σ客户 = 公司口径，差异 ≤ 0.5%（接单未税 / 出货未税 / 应收余额 / 退货退款）。
2. **可穿透**：任一客户任一指标可下钻到订单 / 发货 / 退货 / 应收明细行（`metric_trace.dwd_row_id`）；回款类三项待定，不计入本期验收。
3. **可回补**：任意历史月份可重算，保留 `calc_version`。
4. **开放接口可用**：`level=customer` 取到「年月 × 客户」长表 / 宽表 / 合计，`customer_codes` 过滤与 `allow_customer_detail` 开关生效。
