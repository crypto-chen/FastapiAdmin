# 订单全链路开放接口对接说明（外部系统）

> 版本：v1.0
> 日期：2026-10-13
> 适用：BI 报表、数据仓库、ERP/CRM、Excel 插件、脚本等外部系统**只读**拉取订单全链路明细
> 接口前缀：`/open/v1`（与内部管理端 `/order/*` 物理隔离，网关只需放行 `/open/**`）

---

## 1. 三步接入

1. **申请接入**：向管理员提供用途与 IP，拿到 `app_id`、`app_secret`（密钥只下发一次），
   并让管理员为该应用开启 **`allow_order_detail`**（明细权限）与 **`allow_cost_fields`**（成本字段权限，按需）。
2. **换令牌**：`POST /open/v1/auth/token`，拿 `access_token`（默认有效期 2 小时，过期重换即可）。
3. **拉数据**：带 `Authorization: Bearer <access_token>` 调 `GET /open/v1/orders`。

```bash
# 1) 换令牌
curl -X POST "https://<后台域名>/open/v1/auth/token" \
  -H "Content-Type: application/json" \
  -d '{"app_id":"<你的app_id>","app_secret":"<你的密钥>"}'

# 2) 拉某个期间的订单明细（把 access_token 填进来）
curl -X GET "https://<后台域名>/open/v1/orders?period_value=2026-09&page_no=1&page_size=500" \
  -H "Authorization: Bearer <access_token>"
```

> 开发环境地址：`http://127.0.0.1:8001`

## 2. 鉴权与权限

### 2.1 换令牌（client_credentials）

```
POST /open/v1/auth/token
Content-Type: application/json

{ "app_id": "your_app", "app_secret": "******" }
```

```json
{
  "code": 0,
  "msg": "获取令牌成功",
  "data": {
    "access_token": "eyJhbGciOi...",
    "token_type": "Bearer",
    "expires_in": 7200
  },
  "status_code": 200,
  "success": true
}
```

业务接口统一带 `Authorization: Bearer <access_token>`。

> **判断成功看 `code == 0` 或 `success == true`**，不要看 `code` 是否等于 200；真正的 HTTP 状态码在 `status_code` 字段。

建议：令牌过期前 5 分钟主动续期；收到 `401` 时重新换令牌后重试一次。

### 2.2 应用级权限（管理员侧配置）

| 配置项 | 作用 | 默认 |
| --- | --- | --- |
| `allow_order_detail` | **必须开启**，否则所有订单接口返回 403 | 关闭 |
| `allow_cost_fields` | 是否允许读取敏感数值字段（成本 9 个 + `payment_amount` + `ar_balance`，共 11 个）；关闭时字段目录与数据都会剔除，字段数 57 → 46 | 关闭 |
| `order_scope` | 限定可拉取的订单范围，支持 `{"trade_type": "domestic"}` 或 `"export"`；不传 = 不限 | 空 |
| `ip_whitelist` | 调用方 IP 白名单（逗号分隔），不在名单内直接 401 | 空（不限） |
| `rate_limit` | 每分钟最大请求数 | 600 |
| `token_ttl_seconds` | 令牌有效期（秒） | 7200 |

## 4. 接口详情

### 4.1 字段目录 `GET /open/v1/orders/fields`

外部系统**先拉字段目录**，再按需拼装自己的表结构。字段会增删，`schema_version` 变了就说明字段集有变化。

```json
{
  "code": 0,
  "msg": "查询字段目录成功",
  "data": {
    "schema_version": "2026-10-13",
    "fields": [
      {
        "field_code": "order_number",
        "field_name": "订单号",
        "data_type": "string",
        "group": "基础",
        "sensitive": false,
        "stored_in": "core"
      }
    ]
  },
  "status_code": 200,
  "success": true
}
```

| 返回字段 | 说明 |
| --- | --- |
| `schema_version` | 字段集版本（日期串）。变更时会更新，外部可据此触发重新建表/加列 |
| `field_code` | 字段编码（**外部系统只认这个，不要依赖中文名**） |
| `data_type` | `string` / `number` / `date` |
| `group` | 分组：基础、维度、节点、金额、生产、成本、回款、状态、周期、质量 |
| `sensitive` | 是否成本类敏感字段（受 `allow_cost_fields` 控制） |
| `stored_in` | `core`（落物理列）/ `extra`（落扩展区）；对外使用时忽略即可 |

### 4.2 订单明细 `GET /open/v1/orders`

**请求参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `period_value` | string | 否 | 最新期间 | 期间（`YYYY-MM`），按**接单月**归档 |
| `calc_version` | int | 否 | 最新版本 | 计算版本；不传取该期间最新版本 |
| `order_number` | string | 否 | - | 订单号模糊查询 |
| `trade_type` | string | 否 | - | `domestic`（内贸）/ `export`（外贸） |
| `page_no` | int | 否 | 1 | 页码 |

### 成本（9，默认不对外，需 `allow_cost_fields`）

| field_code | 名称 | 类型 | 敏感 |
| --- | --- | --- | --- |
| `unit_cost` | 标准单位成本 | number | 是 |
| `material_cost_unit` | 标准材料成本 | number | 是 |
| `material_cost_basis` | 材料成本（标准材料成本 × 入库数量） | number | 是 |
| `total_cost` | 订单总成本 | number | 是 |
| `cost_basis` | 毛利扣减成本（标准单位成本 × 入库数量） | number | 是 |
| `gross_profit` | 订单毛利 | number | 是 |
| `gross_profit_rate` | 订单毛利率 | number | 是 |
| `contribution_margin` | 订单边际贡献 | number | 是 |
| `contribution_margin_rate` | 订单边际贡献率 | number | 是 |

**成本与毛利的计算口径**（外部对账时按这个验算）

```
标准单位成本   unit_cost        = (材料费 material_cost_total + 加工费 process_cost_total) ÷ 订单数量 qty
入库数量       inbound_qty      = 生产订单里「整机」分录的合格入库数量（不是各分录求和）
毛利扣减成本   cost_basis       = 标准单位成本 × 入库数量
入库未税       inbound_untaxed  = 毛利扣减成本（已入库部分的成本，同一口径）
订单毛利       gross_profit     = 净出货 − 毛利扣减成本
订单毛利率     gross_profit_rate= 订单毛利 ÷ 净出货（小数，0.604913 = 60.49%）

材料成本       material_cost_basis     = 标准材料成本 × 入库数量
订单边际贡献   contribution_margin     = 净出货 − 材料成本（只扣材料，加工费不计入变动成本）
订单边际贡献率 contribution_margin_rate= 订单边际贡献 ÷ 净出货
```

> 举例：某单接单 2 台、材料费 1036.008 + 加工费 872.996 = 1909.004 → 标准单位成本 954.502；
> 入库 2 台 → 毛利扣减成本 1909.004；净出货 4831.86 → **订单毛利 2922.856、毛利率 60.49%**；
> 其中材料费 1036.008 → **订单边际贡献 3795.852、边际贡献率 78.56%**。<br>
> `total_cost`（订单总成本）是材料费+加工费的**整单合计**，仅作参考，不参与毛利计算。

## 6. 同步方案

### 6.1 数据组织方式

- **一行一单**，主键是 `order_number`。
- 按月归档：`period_value` = 订单的**接单月**。当前已覆盖 **2024-10 ~ 2026-10（25 个月）**。
- 每个月的数据会**持续更新**（出货、入库、成本在后续月份才产生），每次更新产生新的 `calc_version`。
  **接口默认返回最新版本，外部无需关心版本号**；如需回溯某次快照可显式传 `calc_version`。

### 6.2 推荐同步流程

| 时机 | 动作 |
| --- | --- |
| 首次接入 | 逐月拉取历史（2024-10 起），每月翻页到 `has_more = false` |
| 每日 | 拉**当月**（`period_value` = 当前月）全量覆盖 |
| 每月 1 日 | 再拉一次**上月**（上月最后一天的数据在次月才结算完） |
| 字段探测 | 每次启动时调 `/open/v1/orders/fields`，`schema_version` 变了就调整表结构 |

### 6.3 幂等写入

按 `order_number` 做 upsert（先删后插 / `ON DUPLICATE KEY UPDATE` 都可），
拉取到一半失败可以直接重跑当期，不会产生重复数据。

### 6.4 示例：Python 全量同步一个月

```python
import httpx

BASE = "https://<后台域名>"
APP_ID, APP_SECRET = "<app_id>", "<app_secret>"


def get_token() -> str:
    r = httpx.post(f"{BASE}/open/v1/auth/token",
                   json={"app_id": APP_ID, "app_secret": APP_SECRET}, timeout=30)
    body = r.json()
    if body.get("code") != 0:
        raise RuntimeError(f"换令牌失败: {body}")
    return body["data"]["access_token"]


def fetch_period(period: str) -> list[dict]:
    token = get_token()
    headers = {"Authorization": f"Bearer {token}"}
    rows, page_no = [], 1
    while True:
        r = httpx.get(f"{BASE}/open/v1/orders", headers=headers, timeout=120,
                      params={"period_value": period, "page_no": page_no, "page_size": 2000})
        body = r.json()
        if body.get("code") != 0:
            raise RuntimeError(f"拉取失败: {body}")
        data = body["data"]
        rows.extend(item["fields"] for item in data["rows"])
        print(f"{period} 第 {page_no} 页，累计 {len(rows)}/{data['total']}")
        if not data.get("has_more"):
            break
        page_no += 1
    return rows


if __name__ == "__main__":
    orders = fetch_period("2026-09")
    print("本期间订单数:", len(orders))
```

## 7. 错误码

| HTTP | `code` | 说明 | 处理建议 |
| --- | --- | --- | --- |
| 200 | 0 | 成功 | - |
| 401 | 40100 | 令牌无效 / 过期 / 应用停用 / IP 不在白名单 | 重新换令牌；仍失败找管理员核对 IP 与应用状态 |
| 403 | 40101 | 应用未开通订单明细权限（`allow_order_detail` 未开） | 找管理员开通 |
| 404 | -1 | 订单不存在 | 核对订单号 |
| 422 | 1 | 参数不合法（如 `page_size` 超过 2000、`page_no` 小于 1），`msg` 里给出具体原因 | 按 `msg` 修正参数 |
| 429 | 40103 | 触发限流（默认 600 次/分钟） | 降低频率或找管理员调高 `rate_limit` |

> 其它业务码：`40102` 指标类接口无权限、`40104` 参数不合法（管理端接口）。

## 8. 已知数据边界（提前告知，避免误判为接口问题）

| 现象 | 原因 | 影响期间 |
| --- | --- | --- |
| 成本类字段为空（`cost_missing`，缺失率 40%~70%） | 上游 CRM 成本字段那段期间填充率低 | 2024-10 ~ 2025-07 |
| 成本缺失率降到 2%~13% | 上游填充率提升 | 2025-08 之后 |
| `mo_numbers` / `inbound_qty` / `production_cycle` 为空 | 金蝶生产订单（PRD_MO）从 2025-05 才有数据 | 2024-10 ~ 2025-04 |
| `customer_name` / `salesman_name` / `size` / `order_type` / `is_new` 等为空 | CRM 于 2026-10-13 调整了订单明细接口，裁掉了这些字段；当月无历史完整批次可回填 | 2026-10 |
| `contribution_margin` / `contribution_margin_rate` 为空 | 需先有「标准材料成本」与「入库数量」（即要关联到生产订单） | 未关联生产订单的订单 |
| `payment_amount` / `ar_balance` / `overdue_days` | 实际回款需金蝶收款单；应收/逾期是客户维度，未打通到订单维度 | 全部 |

**建议**：落地时对这些字段做空值容错；`data_quality_flag` 可作为数据可用性判断依据。

## 9. 限流与调用日志

- 限流：默认 **600 次/分钟/应用**，超限返回 429。
- 调用日志：每次调用记录在 `open_api_log`（应用、路径、耗时、状态码、调用方 IP），
  排障时管理员可按 `app_id` 检索。
- 单次最多 2000 行，一个月约 1~4 千单，**通常 1~3 页拉完**。

## 11. 变更管理

| 变更类型 | 表现 | 外部系统要做的事 |
| --- | --- | --- |
| 新增字段 | `/open/v1/orders/fields` 多一项，`schema_version` 更新 | 新字段可选，不处理也不影响 |
| 字段来源调整 | 值变化，字段不变 | 无 |
| 字段下线 | 目录里 `field_code` 消失 | 按目录动态建表可自动兼容 |
| 口径调整 | 同期间 `calc_version` 递增，值变化 | 重新拉取该期间覆盖 |

**对接建议：把 `field_code` 作为唯一键，不要用中文名；报表列顺序从目录里读。**
