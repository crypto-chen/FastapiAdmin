# 指标开放接口对接说明（外部系统）

> 版本：v1.0
> 日期：2026-09-28
> 适用：BI 报表、ERP/CRM、Excel 插件、脚本等外部系统只读调用核算指标结果
>
> 只想看「有哪些指标 + 怎么调」：直接给对方 `docs/指标接口清单与调用方案.md`
> （由 `backend/scripts/gen_metric_api_doc.py` 从数据库自动生成，含全部指标编码、口径与可调用示例）。

---

## 1. 三步接入

1. 向管理员申请接入：拿到 `app_id`、`app_secret`（密钥只下发一次）。
2. 换令牌：`POST /open/v1/auth/token`，拿 `access_token`（有效期默认 2 小时，过期重新换即可）。
3. 取数：带 `Authorization: Bearer <access_token>` 调 `POST /open/v1/metrics/query`。

```bash
# 1) 换令牌
curl -X POST "https://<后台域名>/open/v1/auth/token" \
  -H "Content-Type: application/json" \
  -d '{"app_id":"bi_report","app_secret":"你的密钥"}'

# 2) 取数（把上一步的 access_token 填进来）
curl -X POST "https://<后台域名>/open/v1/metrics/query" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <access_token>" \
  -d '{
        "metrics": ["marketing_office_expense", "marketing_travel_expense"],
        "period_type": "month",
        "period_start": "2026-01",
        "period_end": "2026-09"
      }'
```

## 2. 接口清单

| 方法 | 路径 | 用途 | 是否需要令牌 |
|------|------|------|--------------|
| POST | `/open/v1/auth/token` | 应用凭证换访问令牌 | 否 |
| GET | `/open/v1/metrics` | 查询可读指标目录（编码、名称、期间类型、口径说明） | 是 |
| POST | `/open/v1/metrics/query` | 批量取数（主接口） | 是 |
| GET | `/open/v1/orgs` | 查询可见组织（编码、名称、上级、层级） | 是 |
| POST | `/open/v1/metrics/{code}/run` | 触发指标重算（默认未开放） | 是 |

### 2.1 换令牌

```json
{ "app_id": "bi_report", "app_secret": "******", "grant_type": "client_credentials" }
```

```json
{
  "code": 0, "msg": "获取令牌成功", "success": true, "status_code": 200,
  "data": { "access_token": "eyJ...", "token_type": "Bearer", "expires_in": 7200 }
}
```

> **成功时 `code` 是 `0`（不是 200）**：判断成功请看 `code == 0` 或 `success == true`；`status_code` 字段才是 HTTP 状态码。

建议：在令牌过期前 5 分钟主动续期；收到 `401 / 40100` 时重新换令牌后重试一次。

### 2.2 批量取数请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `metrics` | string[] | 是 | 指标标识，单次最多 20 个；可传系统指标编码（`marketing_office_expense`）或 **Excel 科目编码**（`EXP-01-a`） |
| `period_type` | string | 否 | `month`（默认）/ `day` / `week` / `year` |
| `period_start` | string | 否 | 起始期间（含），如 `2026-01`；不传取当前期间 |
| `period_end` | string | 否 | 结束期间（含），如 `2026-09` |
| `org_codes` | string[] | 否 | 组织编码；不传 = 授权范围内全部组织 |
| `level` | string | 否 | `org`（默认，仅组织合计）/ `dept` / `all`（需应用开通明细权限） |
| `format` | string | 否 | `long`（默认，长表）/ `wide`（宽表） |
| `total_only` | bool | 否 | `true` 时只返回合计：按「指标 × 期间」汇总，`items` 为空，结果在 `totals` 中 |
| `include_meta` | bool | 否 | 默认 `true`，返回指标名称、单位、口径说明 |

期间格式：月 `2026-09`、日 `2026-09-28`、年 `2026`。单次期间跨度上限：月 36 个、日 366 个、年 10 个。

### 2.3 批量取数响应（长表）

```json
{
  "code": 0, "msg": "查询成功", "success": true, "status_code": 200,
  "data": {
    "period_type": "month",
    "period_start": "2026-08",
    "period_end": "2026-08",
    "level": "org",
    "calc_version_policy": "latest",
    "metrics": [
      { "code": "marketing_office_expense", "name": "营销中心办公费用", "period_type": "month", "unit": "元",
        "dimensions": ["dept"], "description": "科目 6601 当期借方发生额汇总" }
    ],
    "items": [
      {
        "metric_code": "marketing_office_expense",
        "metric_name": "营销中心办公费用",
        "period_value": "2026-08",
        "org_code": "01",
        "org_name": "永锢科技",
        "dept_code": null,
        "dept_name": null,
        "value": 12345.67,
        "calc_version": 3,
        "calc_time": "2026-09-28 02:30:11",
        "batch_id": "202609280230"
      }
    ],
    "errors": [],
    "summary": {
      "metric_count": 1, "item_count": 1, "period_start": "2026-08", "period_end": "2026-08",
      "period_count": 1, "org_count": 1, "total": 12345.67
    }
  }
}
```

字段说明：

- `value` 单位为元，保留 4 位小数；`calc_version` / `calc_time` / `batch_id` 用于判断数据新鲜度。
- 每行同时返回 `metric_code`（系统编码）与 **`excel_code`（Excel 科目编码）**，可直接与财务底稿对账；`data.metrics[]` 里也有对应字段。
- 默认只返回每个「指标 × 期间」的**最新计算版本**结果。
- **只返回存在的行**：某组织某期间没有数据时不会补 0，请自行按 0 处理。
- `level=org`（默认）时 `dept_code` / `dept_name` 恒为 `null`。

> 完整的「Excel 科目编码 ↔ 指标编码」对照表见 `docs/指标接口清单与调用方案.md` 第 5.2 节（自动生成）。

宽表（`"format": "wide"`）把指标编码变成列，一行一个「期间 × 组织」：

```json
{
  "data": {
    "columns": ["period_value", "org_code", "org_name", "dept_code", "dept_name", "marketing_office_expense"],
    "rows": [
      { "period_value": "2026-08", "org_code": "01", "org_name": "永锢科技", "dept_code": null, "dept_name": null,
        "marketing_office_expense": 12345.67 }
    ]
  }
}
```

建议使用长表：新增指标时列不变，解析代码无需改动。

### 2.3.1 只要合计值（推荐给「只看总数」的场景）

不传 `org_codes`（或不关心组织）时加 `"total_only": true`，直接拿合计，不再返回逐组织明细：

```json
{
  "metrics": ["marketing_office_expense"],
  "period_type": "month",
  "period_start": "2026-09",
  "period_end": "2026-09",
  "total_only": true
}
```

```json
{
  "code": 0, "msg": "查询成功", "success": true,
  "data": {
    "period_type": "month", "period_start": "2026-09", "period_end": "2026-09",
    "total_only": true,
    "metrics": [ { "code": "marketing_office_expense", "name": "营销中心办公费用", "unit": "元" } ],
    "totals": [
      { "metric_code": "marketing_office_expense", "metric_name": "营销中心办公费用",
        "period_value": "2026-09", "value": 6871.01, "calc_version": 1,
        "calc_time": "2026-09-27 03:59:42", "org_count": 14 }
    ],
    "items": [],
    "errors": [],
    "summary": { "metric_count": 1, "item_count": 14, "org_count": 14, "total": 6871.01 }
  }
}
```

要点：

- 一个指标看一个数 → `metrics` 传单元素数组，取 `data.totals[0].value`。
- 多个期间 → `totals` 按期间各返回一行，`period_value` 区分。
- 该模式只对应用有权查看的组织求和；`org_count` 是参与合计的组织数。
- `total_only` 优先于 `format`，此时不返回 `rows`/`items`。

### 2.4 部分指标不可读

请求里混入不存在或已停用的指标编码时，接口仍返回 `200`，不可读的编码在 `errors` 中逐条说明：

```json
{ "errors": [ { "metric_code": "not_exists", "reason": "指标不存在" } ] }
```

如果请求的所有指标都不可读，则返回 `403 / 40102`。

## 3. 错误码与限流

| 业务码 | HTTP | 含义 | 处理建议 |
|--------|------|------|----------|
| 0 | 200 | 成功（业务码 `0`） | — |
| 40100 | 401 | 未带令牌 / 令牌无效 / 令牌过期 | 重新换令牌 |
| 40101 | 403 | 应用被停用 / 凭证过期 / IP 不在白名单 | 联系管理员 |
| 40102 | 403 | 指标未授权（如申请了明细但应用未开通） | 联系管理员 |
| 40103 | 429 | 超出调用频率 | 按提示秒数退避后重试 |
| 40104 | 400 | 参数非法（期间格式、跨度超限、指标数超限等） | 修正请求参数 |
| 40105 | 500 | 服务内部错误 | 把响应体 `msg` 与请求时间反馈给管理员 |

限流：

- 业务接口默认每个应用 **600 次/分钟**（可由管理员按应用调整）；超限返回 `40103`，提示信息中含建议等待秒数。
- 换令牌接口单独限制 **30 次/分钟**，不影响业务配额。

建议客户端：拉取月度全量指标时一次传完全部指标编码 + 期间区间，不要按指标逐个请求。

## 4. 常见问题

1. **返回 `items` 为空**：该期间尚未计算或未同步。先确认 `GET /open/v1/metrics` 能看到该指标，再联系管理员触发重算。
2. **`value` 与后台页面不一致**：确认 `calc_version`；页面与接口都取最新版本，若页面刚重算过，请重新请求。
3. **`org_code` 为 `null`**：该行来自未映射到标准组织的机构（仅在不限制组织范围时可能出现）。
4. **要部门/客户明细**：默认只给组织合计，需要管理员在「开放接口 → 接入应用」里开启「核算维度明细」。
5. **数据什么时候更新**：月指标每日 02:30 重算当月，次月 1 日补算上月；建议每天早上 8 点后取数。
